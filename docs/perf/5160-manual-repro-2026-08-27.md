# Manual repro: #5160 deckgl layer-toggles header INP (2026-08-27)

Validation result for [#5160](https://github.com/koala73/worldmonitor/issues/5160), for
starting a fresh conversation. Branch `fix-5160`. No repo files changed.

## Verdict

Field signal is real (7 desktop interactions, ~11.7s). The issue's title/location/
hypothesis are wrong — do not patch the collapse handler.

`.toggle-header` has no click listener. Confirmed on current HEAD:

- [src/components/DeckGLMap.ts:5454](../../src/components/DeckGLMap.ts#L5454) — header
  div wraps a `<span>` + two buttons; listeners bind only to `.layer-help-btn`
  ([:5590](../../src/components/DeckGLMap.ts#L5590)) and `.toggle-collapse`
  ([:5606](../../src/components/DeckGLMap.ts#L5606)). Header div + title span are inert.
- Globe mirror identical: [src/components/GlobeMap.ts:1966](../../src/components/GlobeMap.ts#L1966),
  listener on `.toggle-collapse` at [:2071](../../src/components/GlobeMap.ts#L2071).
- Collapse handler itself is `classList.toggle('collapsed')` + `display:none`
  ([src/styles/main.css:18102](../../src/styles/main.css#L18102)) + chevron swap. No
  transition, no `render()`, no `updateLayers()` — `processingDuration` is ~0 by
  construction. 11.7s is `inputDelay + presentationDelay`, i.e. ambient jank, not this
  handler.

**Why the header selector:** web-vitals 5.3.0 `getSelector`
([node_modules/web-vitals/dist/modules/lib/getSelector.js:23](../../node_modules/web-vitals/dist/modules/lib/getSelector.js#L23))
builds the selector upward from the raw event target. A selector ending in
`div.toggle-header` means the user's click landed on the header div itself — missing the
small `.toggle-collapse` chevron — most likely while the panel was interactive but the
map was still mid-init.

**Actual mechanism:** [src/components/DeckGLMap.ts:877-881](../../src/components/DeckGLMap.ts#L877-L881) —
`createLayerToggles()` runs synchronously one line after `initMapLibre()` kicks off, so
the layer panel paints and becomes clickable during MapLibre style-load + WebGL shader
compile + first deck.gl commits. Constructor only fires after the renderer demand gate
resolves ([src/components/MapContainer.ts:452-456](../../src/components/MapContainer.ts#L452-L456)).
Two real bugs, neither the one filed: (1) init-jank window where interactive chrome
paints before the thread is free; (2) header looks clickable (carries the chevron
visually) but only the ~10px button actually is — no feedback, so users re-click,
generating more poor INP events.

**Caveat on the number:** `11,744ms (n=7)` is a p75 of captured Sentry events, and
[src/bootstrap/inp-report.ts:57](../../src/bootstrap/inp-report.ts#L57) drops `good`
events then samples survivors at 50%. Per
[docs/perf/reading-field-web-vitals.md](reading-field-web-vitals.md) that statistic is
inverted (p75 of the bad tail only). Use bad-event rate + CrUX, not this number, in any
PR.

**Unverified:** the raw Sentry `interactionTarget` string (issue paraphrases it; real
`getSelector` output has no spaces, includes tag names). Pull `extra.interactionTarget`
from one of the 7 events — if it ends `>button.toggle-collapse` instead of
`div.toggle-header`, the target was the chevron, not the header. Doesn't change the
conclusion (handler is ~1ms either way) but decides whether "make header clickable" is
part of the fix.

## Manual reproduction

[src/components/MapContainer.ts:251-264](../../src/components/MapContainer.ts#L251-L264)
`hasWebGLSupport()` rejects `swiftshader`/`llvmpipe`/`softpipe`/"software rasterizer" and
falls back to SVG mode.

- Real GPU, **headed** Chrome — not headless, not a VM/RDP session.
- Desktop viewport (`isMobileDevice()` must be false), 1365×768.
- Do **not** use `playwright.config.ts` (line 49 forces `--use-angle=swiftshader`) or run
  `scripts/measure-dashboard-render-axis.mjs` as-is (line 907 `chromium.launch()` is


## Recommendation for next conversation

Retitle/rescope #5160 rather than patch the collapse handler. Two candidate fixes,
neither at the filed location, can ship independently:

1. Don't paint the layer panel until MapLibre's `load` fires (or gate it behind the same
   deferred-heavy-data path as the layer commits) — removes the click target from the
   jank window entirely.
2. Move the collapse listener onto `.toggle-header` with `cursor: pointer` +
   `role="button"` — kills the dead-click re-click loop that generates the events.

Then verify against the issue's stated acceptance criteria (Sentry bad-event rate for
this selector -> ~0; DebugBear desktop `inpSelector` p75 < 500ms), not a generic lab
score.

## Resolution (shipped on `fix-5160`)

Both recommendations above shipped, plus the state replay the deferral required.

**1. Panel out of the init window** — [DeckGLMap.ts](../../src/components/DeckGLMap.ts)
`scheduleLayerTogglesMount()`. The constructor schedules instead of building; the mount
order is basemap `load` -> idle slot -> build, with an 8s ceiling so the panel still
appears if `load` never fires. The ceiling sits high on purpose: a tight one fires first
on exactly the slow, CPU-throttled sessions that produced these events and would drop
the panel back into the burst. Nothing is lost by waiting — before the basemap draws
there is nothing for a layer toggle to act on.

This also removes ~30 rows of DOM build plus ~90 listener binds from the same task as
MapLibre style parse, so it is a real main-thread reduction, not only a change of
selector attribution.

**2. Header is the click target** — new `bindLayerPanelCollapse()` in
[map-layer-definitions.ts](../../src/config/map-layer-definitions.ts), shared by both
renderers so they cannot drift apart again. The chevron stays the accessible control (a
real `<button>` carrying `aria-expanded`) and its click bubbles into the same handler,
so there is exactly one toggle per click and no second tab stop. `.layer-help-btn` is
excluded. CSS adds `cursor: pointer` + `user-select: none` to the header.

`role="button"` on the header was deliberately **not** added: it would make the header a
second tab stop for an action the chevron already exposes.

**State replay** — `MapContainer.rehydrateActiveMap()` and the data loaders push
hidden/loading/ready state synchronously right after construction, i.e. before the panel
now exists. `hideLayerToggle` / `setLayerLoading` / `setLayerReady` record into
`hiddenLayerToggles` / `layerToggleLoading` / `layerToggleReady`, and the deferred mount
replays them. Without this the pushes land on an empty container and are lost.
